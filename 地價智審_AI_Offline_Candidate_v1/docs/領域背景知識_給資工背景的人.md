## 1. 這題到底在幹嘛

政府要蓋路、蓋捷運，需要徵收私人土地。徵收要照**市價**賠償地主。
所以必須有人先回答一個問題：**「這塊地值多少錢？」**

回答這個問題的過程叫「查估」，寫下來的表格叫「查估書表」。

實務上是估價師填表、地政局審查人員逐項核對。審查很痛苦，因為：

- 表單多，要跨表比對
- 每個欄位都要查一本「評價基準明細表」才知道該填什麼
- 修正率要加總、要抄到別張表，容易抄錯算錯

【官方・命題文件】痛點原文：
> 「人工逐項比對耗時且易發生疏漏」「人工判讀一致性不易維持」
> 「修正率加總及跨表抄填容易出現計算或填載錯誤」

## 2. 五個名詞（先記這五個就好）

| 名詞 | 白話 | 範例中的值 |
|---|---|---|
| **宗地** | 一筆土地。就是一個地號。 | 金山區金美段489地號 |
| **地價區段** | 一群條件相近的宗地，打包成一個單位一起評估。像是「分群」。 | P002-00 |
| **比準地** | 從區段裡挑一筆當代表，算出它的價格，代表整個區段。 | 金美段489地號 |
| **比較標的** | 附近**真的成交過**的案子，拿來當比價基準。 | 溫泉段218地號，114.05.28 成交 184,763 元/M² |
| **區域因素 / 個別因素** | 區域＝整個區段共通的（交通、公共設施、污染）。個別＝這一筆地自己的（面積、形狀、臨路）。 | 見第 7 節清單 |

**核心方法叫「比較法」**，邏輯很簡單：

```
隔壁那塊地真的賣了 184,763
  → 但它跟我們要估的地不完全一樣
  → 逐項算出「差多少」
  → 修正回來，就是我們要的價格
```

## 3. 「優劣等級」到底是什麼

這是全題最關鍵、也最容易卡住的概念。**它就是一個 ordinal enum。**

```
優 → 稍優 → 普通 → 稍劣 → 劣
1     2      3      4      5      ← rank
```

**⚠️ 等級數不是固定 5 級。** 作業手冊 p.49-50【官方】明列合法的分級方式：

| 分幾級 | 等級名稱 |
|---|---|
| 2 級 | 優／劣 |
| 3 級 | 優／普通／劣 |
| 5 級 | 優／稍優／普通／稍劣／劣 |
| 5 級（變體A） | 無／輕微／中度／嚴重／極嚴重 |
| 5 級（變體B） | 極輕微／輕微／普通／嚴格／極嚴格 |
| 7 級 | 極優／優／稍優／普通／稍劣／劣／極劣 |
| 9 級 | 超極優／極優／優／稍優／普通／稍劣／劣／極劣／超極劣 |

> ※分為 9 級以上者由直轄市或縣(市)地政機關**自行決定**等級細項。

**金山區這一份**剛好只用到 2／3／5 級（多數 5 級；「都市計畫內外」「形狀」
「停車方便性」是 2 級；個別因素「地勢」是 3 級）。**但那是這一份的實況，
不是通則** —— 換一個區段可能出現 7 級或 9 級，等級名稱也可能整組不同。

**對系統的意涵：等級數與等級名稱都不能寫死。**

### 怎麼決定某個因素是「優」還是「劣」？

查「**評價基準明細表**」。它就是一張 lookup table，把原始值分桶。

分級門檻印在明細表**最右邊的「備註」欄**。以「主要道路寬度」為例
（`評價基準明細表範例.pdf` **第 2 頁**，交通運輸大類，逐字原文）：

```
以區段內主要道路寬度來衡量
優：   30m以上
稍優： 20m以上未滿30m
普通： 15m以上未滿20m
稍劣： 10m以上未滿15m
劣：   未滿10m或無
```

整理成表，並補上序位：

| 原始值 | 等級 | rank |
|---|---|---|
| 30m 以上 | 優 | 1 |
| 20m 以上未滿 30m | 稍優 | 2 |
| 15m 以上未滿 20m | 普通 | 3 |
| 10m 以上未滿 15m | 稍劣 | 4 |
| 未滿 10m 或無 | 劣 | 5 |

> **來源說明（重要）**：前兩欄（原始值、等級）逐字抄自
> `評價基準明細表範例.pdf` p.2 備註欄。
> **第三欄 rank 不在明細表裡** —— 明細表只印中文等級名稱，不印數字。
> 這組編號的依據在另一份檔案：`查估書表範本.pdf` 表1 每列左邊印了
> `(等級, 總等級數)`，主要道路那列是 `3 5`；表5-2 同一列印
> `主要道路寬度 3 普通`。也就是**官方自己把「普通」寫成 3**，
> 本文件只是把 優=1／稍優=2／普通=3／稍劣=4／劣=5 的完整序位補齊，
> 並用 28 個因素交叉驗證（28/28 吻合，見第 5 節「表1 藏了一個關鍵欄位」）。

範例中比準地的主要道路是「中山路，寬度 18M」（表1 原文）
→ 落在「15 以上未滿 20」→ **普通**
→ 表1 該列左邊印 `3 5`、表5-2 印 `3 普通` → **rank 3**

**這一步本質上就是 `bisect()`。** 給定一個數值和一組門檻，回傳桶號。
完全 deterministic，沒有任何模糊判斷空間。

> ⚠️ 但有例外：有些因素不是數值分桶，而是文字判定。
> 例如「顧客通行量之多寡」的等級是「顧客通行量多／稍多／普通／較少／少」，
> 「排水之良否」是「排水系統完善不曾淹水／有排水系統不易淹水／…」。
> 這類要靠現場勘查描述，**不是純計算**，是 AI 輔助＋人工確認的地帶。

## 4. 修正率矩陣：整題的數學核心

知道等級之後，怎麼換算成百分比？查一個矩陣。

每個因素在明細表裡都附一張表，**列 = 比準地的等級，行 = 比較標的的等級**，
格子裡就是修正率。以「容積率」為例（最大修正率 40）：

|  比準地＼比較標的 | 優 | 稍優 | 普通 | 稍劣 | 劣 |
|---|---|---|---|---|---|
| **優**   | 0 | 10 | 20 | 30 | 40 |
| **稍優** | -10 | 0 | 10 | 20 | 30 |
| **普通** | -20 | -10 | 0 | 10 | 20 |
| **稍劣** | -30 | -20 | -10 | 0 | 10 |
| **劣**   | -40 | -30 | -20 | -10 | 0 |

看出規律了嗎？這張表**不需要背，可以算出來**：

```
級距   = 最大修正率 ÷ (等級數 - 1)
調整率 = (比較標的rank - 比準地rank) × 級距
```

容積率：級距 = 40 ÷ 4 = 10。比準地優(1)、比較標的劣(5) → (5-1)×10 = **+40**。

> **本文件作者已用範例明細表中 12 個不同因素（含 2 級／3 級／5 級、
> 正值與負值）實際驗算，12/12 全部吻合。** 這條公式對整份明細表成立。

### 為什麼是 (比較標的 − 比準地)？

因為修正的方向是「把比較標的的價格調整成比準地的價格」。
比較標的**比較差**（rank 大）→ 比準地比較好 → 要**往上**調 → 正值。直覺是通的。

### 每個因素的「最大修正率」在哪看？

明細表每個因素左下角有個**黃色標記的數字**，那就是該因素的最大修正率（級距上限）。
例如容積率是 40、主要道路寬度是 15、接近觀光遊憩設施是 3。

**這個數字每個區段／每種用地類別可能不同** —— 這正是為什麼比賽當天會另外
發一份該區段的明細表【官方，00:27:18】。你的系統必須能吃新的明細表，
不能把金山區的數字寫死。

## 6. 完整實例：212,958 是怎麼算出來的

這是範本裡的正確答案。整條鏈拆開如下。

### Step 0：比較標的的事實

```
溫泉段218地號，114.05.28 成交，土地正常單價 184,763 元/M²
```

### Step 1：期日調整 +2.00%

成交日到估價基準日之間，地價漲了。範本備註欄寫得很清楚：

> 依第64期都市地價指數，金山區商業區年漲幅 6.18%(108.16%-101.98%)，
> 推估價格日期當時指數 48,481 元/㎡，比較標的交易日當時 47,513 元/㎡，
> 調整率約 2%〔(48,481/47,513)-1〕

```
184,763 → 188,459 元/M²
```

### Step 2：區域因素調整 0.00%

**為什麼是 0？** 因為比較標的溫泉段218 和比準地金美段489 **在同一個地價區段
P002-00**。同一區段 → 區域條件完全一樣 → 每一項等級都相同 → 差值 0 → 修正率 0。

這就是為什麼範本的表5-2 整張都是 `0.00`。
⚠️ **注意：等級欄還是要填**（都填了 1 優、3 普通、5 劣…），只是相減後為 0。
不要以為表5-2 是空的就不用做。

### Step 3：個別因素調整 +13.00%

這裡才是真正有差異的地方。5 個項目有落差：

| 項目 | 比準地（金美段489） | 比較標的（溫泉段218） | 等級對比 | 修正率 |
|---|---|---|---|---|
| 深度 | 23m → 普通(3) | 16m → 稍劣(4) | (4-3)×1.00 | **+1.00%** |
| 道路種類 | 主要道路 → 優(1) | 次要道路 → 稍優(2) | (2-1)×2.00 | **+2.00%** |
| 面前道路寬度 | 中山路 18M → 稍優(2) | 金包里街 6M → 稍劣(4) | (4-2)×2.50 | **+5.00%** |
| 嫌惡設施 | 公墓 260M → 普通(3) | 公墓 80M → 劣(5) | (5-3)×1.50 | **+3.00%** |
| 停車方便性 | 可路邊停車 → 優(1) | 不可路邊停車 → 劣(2) | (2-1)×2.00 | **+2.00%** |
| | | | **合計** | **+13.00%** |

其餘 14 項（面積、寬度、形狀、臨街情形、地勢、接近學校/市場/公園/車站/商圈、
使用分區、建蔽率、容積率、有無禁限建）兩邊等級相同，修正率 0。

### Step 4：算出價格

```
188,459 × (1 + 0.13) = 212,958.67  →  212,958 元/M²
```

比較標的權重 100%（只有 1 筆），所以**比準地比較價格 = 212,958**。

> 【官方・範本備註欄】為什麼只有 1 筆比較標的？因為該區成交案例稀少，
> 依土地徵收補償市價查估辦法第17條第3項放寬蒐集期間至一年內、
> 第19條第2項擴大蒐集範圍至金山全區，仍無其他合適案例。

## 9. 為什麼這題適合用 AI 做

把上面拆解完，這題的結構其實非常清楚：

| 步驟 | 性質 | 適合誰做 |
|---|---|---|
| 從 PDF 讀出欄位 | OCR／文件擷取 | AI |
| 查各種官方資料（地籍、分區、設施位置） | API／open data | 程式 |
| 算距離 | 幾何計算 | 程式 |
| 數值 → 優劣等級 | 分桶查表 | 程式（deterministic） |
| 等級 → 修正率 | 矩陣查表／公式 | 程式（deterministic） |
| 加總、跨表搬運 | 算術 | 程式 |
| 抓出哪裡填錯／算錯／跨表不一致 | 規則比對 | 程式 |
| 把結果解釋成人話給審查人員看 | 自然語言 | AI／LLM |
| 文字型等級判定（如「顧客通行量多寡」） | 需現場判斷 | AI 建議 + 人工確認 |

**這就是本專案的核心設計原則**：正確性由 deterministic 引擎負責，
LLM 只做解釋與輔助，資料不足時誠實回報 UNKNOWN。

## 11. 具體怎麼填表（操作程序）

依據：作業手冊「伍」章填表說明（p.20-32）＋「六、比較法調查估價表」（p.52-53）。
每一條都用金山範例實際驗算過。

### 填表順序不能亂

```
表1（比準地區段）  表1（比較標的區段）
        │                  │
        └────────┬─────────┘
                 ▼
              表5-2
                 │
                 ▼
               表4
```

⚠️ **每個「地價區段」各要一張表1**。比準地一張，每個比較標的所在區段各一張。
若比較標的與比準地同區段（金山範例就是），才只需一張。

---

### Step 1：表1 地價區段勘查表

對每一列做三件事：

1. **填原始事實** —— 設施名稱、●本區段內／●本區段外(距 ___ M)、道路寬度、
   建蔽率／容積率、現況描述
2. **查等級** —— 拿原始值去對明細表「備註」欄的門檻
3. **寫等級** —— 填在該列左邊的 `(等級序號, 總等級數)` 格子

**量距規則**【官方，逐字稿 00:22:32／00:44:01 覆述兩次】
- 一般設施（交通運輸、公共建設）→ **最近的（步行／路線）距離**
- 特殊設施（殯葬、廢棄物、環境污染）→ **直線距離**
- 量測**起點 = 本區段中心點**（作業手冊 p.28-32，18 次制式文字）
- **全案同一細項的量測標準必須一致**（p.24，這是硬性要求）

**沒有該設施時**：名稱欄填「**無**」，**距離欄留空白**（p.23）。不要填 0。

**同一細項有多個設施時**（多個學校、多個嫌惡設施）：填「**對當地地價影響
最大者**」，且同一徵收範圍填寫基礎需一致（p.24）。
⚠️「影響最大」由查估人員判斷，**不是取最近**——這是人工判斷點。

---

### Step 2：表5-2 影響地價區域因素分析明細表

1. **比準地欄**：抄 Step 1 表1 的等級
2. **比較標的欄**：抄該標的所在區段那張表1 的等級
3. **修正百分比**：查該因素的矩陣 `[列=比準地等級][行=比較標的等級]`
   等同公式 `(比較標的rank − 比準地rank) × 級距`
4. **各大類百分比小計**
5. **影響地價區域因素總修正數 = (1)+(2)+…+(8)**

⚠️ 若比較標的與比準地**同區段**，所有等級相同 → 全部 0.00
（金山範例正是如此）。**但等級欄仍要照填**，不是留白。

---

### Step 3：表4 比較法調查估價表

| 順序 | 欄位 | 怎麼來 |
|---|---|---|
| ① | 0 基本資料、土地正常單價、交易日期 | 題目給（實價登錄／徵收案例） |
| ② | 交易日期 調整百分率 | 都市地價指數推算 |
| ③ | 調整至估價基準日單價 | ① × (1+②) |
| ④ | 區域因素調整百分率 | **抄表5-2 的總修正數** |
| ⑤ | 個別因素 7~25 各項條件 | 填比準地與比較標的的實際值 |
| ⑥ | 各項差異率 | 判等級 → 查個別因素矩陣 |
| ⑦ | 合計 | ⑥ 全部相加（帶正負號） |
| ⑧ | 調整百分率絕對值加總 | **②④⑥全部取絕對值後加總** |
| ⑨ | 價格形成因素之相近程度 | 由 ⑧ 決定，見下表 |
| ⑩ | 試算價格 | ③ × (1+④) × (1+⑦) |
| ⑪ | 比較標的權重 | 由 ⑨ 決定 |
| ⑫ | 比準地比較價格 | Σ(⑩ × ⑪)，四捨五入至個位數 |

**⑧ 的算法**【官方 p.53（十）】「各項調整百分率**先取絕對值後加總**」
金山驗算：`|2.00| + |0.00| + |1|+|2|+|5|+|3|+|2| = 15.00%` ✓ 與表上一致
（注意**期日調整的 2% 也要計入**，不只個別因素）

**⑨⑪ 權重規則**【官方 p.53（十一），依技術規則§27】

| 比較標的數 | 絕對值加總 | 相近程度 | 權重 |
|---|---|---|---|
| 3 件 | 7% / 10% / 15% | 較高 / 普通 / 較低 | 50% / 30% / 20% |
| 2 件 | 7% / 10% | 較高 / 普通 | 70% / 30% |
| **1 件** | — | **普通** | **100%** |

金山範例只有 1 件 → 相近程度「普通」、權重 100% ✓ 完全吻合。

---

### ⚠️ 進位規則：最容易失分的地方

**官方規則**
- 比準地比較價格：**四捨五入至個位數**（p.53（十二））
- 表4 的 8寬度／9深度：小數點以下四捨五入至個位；實測小於 1 公尺者
  填至小數點以下第 2 位（p.22）

**實測發現的陷阱** —— 中間值**不可以**先四捨五入：

```
❌ 用表上顯示的 188,459：
   188,459 × 1.13 = 212,958.67 → 四捨五入 212,959   （差 1 元）

✅ 全程保留精度，只在最後四捨五入：
   184,763 × 1.02   = 188,458.26
   188,458.26 × 1.13 = 212,957.83 → 四捨五入 212,958   （＝官方答案）
```

表上印的「調整至估價基準日單價 188,459」是**顯示值**（188,458.26 進位），
不是計算值。照著顯示值算下去就會錯。

期日調整與因素調整之間是**相乘**不是相加：
`184,763 × 1.15 = 212,477` ✗ 對不上。

> 【推論】④區域％與⑦個別％之間是相乘或相加，因金山範例④=0 無法區分，
> 本文件寫成相乘。若當天區域％不為 0，需回查作業手冊確認。

### 兩條避免重複修正的規則【官方 p.52-53】

- **（九）** 區域因素與個別因素若有雷同項目（例如兩邊都有「建蔽率」「容積率」），
  **若已在區域因素完全反映調整，就不需再做個別因素調整**，反之亦然。
- **3.** 面積、寬度、深度、形狀之間互有關聯，訂表時已考量，
  避免重複修正或因項目免填而忽略未修正。

## 12. 中央上限表（附件一～四）怎麼用

`黑客松參考資料/` 裡的四份 .doc 是**內政部訂定的「最大影響範圍」表**，
作業手冊 p.50 明文指名它：

> 得於備註欄敘明理由後，酌予調整依明細表填載之修正百分比，惟仍應於內政部訂定
> 「影響地價區域因素評價基準表（土地徵收補償市價查估用）」所規定之
> **最大影響範圍內**進行修正調整

| 附件 | 用地類別 | 子級別 |
|---|---|---|
| 一 | 住宅用地 | 高級／中級／普通／村里鄰 |
| 二 | 商業用地 | 高度／中度／普通／村里鄰 |
| 三 | 工業用地 | 大規模／中小規模 |
| 四 | 農業用地 | （無子級別） |

**層級關係**

```
內政部中央表（附件一~四）      定「最大影響範圍」上限，依用地類別×子級別
        ↓ 不得超過
直轄市/縣市 評價基準明細表      定實際級距與各級門檻，原則以鄉鎮市區為單位
        ↓ 可個案微調
個案                            備註欄敘明理由後可調，仍不得超過中央上限
```

**用途**：當天拿到明細表後，可以拿中央表**反向驗證**——若某因素的級距超過
中央上限，那份明細表或你的解讀有問題。這也是一個現成的智慧檢核點。
