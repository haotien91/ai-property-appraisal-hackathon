# 原前端的自動資料填表流程

## 使用方式

請在專案根目錄執行：

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements-local-app.txt
powershell -ExecutionPolicy Bypass -File .\start-app.ps1
```

開啟 `http://127.0.0.1:8000/case-new.html`。畫面與原本的簡化流程一致：上傳查估書及評價基準明細表後，既有欄位會自動擷取；按下「建立案件並開始分析」後，本機後端才開始查詢資料、套用規則及產生表 3、表 5-1、表 4 的六頁正式 PDF。

請從專案根目錄執行 `start-app.ps1`。不要進入 `frontend/app` 建立虛擬環境，也不要用 `python -m http.server`，因為單純的靜態伺服器沒有自動查詢資料與產表 API。

## 資料流程

1. 從上傳 PDF 的文字層擷取案號、區段、行政區、用地類別及區段範圍。
2. 讀取專案內樹林住宅案例的題目固定值、都市計畫與設施快照。
3. 以國土測繪圖資服務雲免金鑰服務查詢行政區、地段、土地利用、道路交叉點及周邊設施。
4. 以 OpenStreetMap Overpass 補充可公開查得的設施與具明示 `width` 的道路寬度。
5. 保留每個欄位的來源、查詢網址、時間、狀態與備選值，再交給既有分級、修正及計算引擎。
6. 產出官方六頁 PDF：表 3 四頁、表 5-1 一頁、表 4 一頁；案件 JSON 與 PDF 一併收入 ZIP。

前端檔案沒有為此功能改寫，`config.js` 也依原檔送出。`scripts/serve_app.py` 只在回應既有 `api.js` 時於記憶體掛上原頁面已預留的 `extractCaseMetadata`、`createCaseWithDocuments` 方法，並把結果頁既有的查詢與下載方法指向本機後端。

## 正確性界線

- 題目或使用者提供的固定值優先，公開資料衝突只保留為備選證據。
- 點位距離是直線距離，公開地圖的現況觀測會標示為需人工複核。
- 查不到、API 失敗或無法由區段邊界證明的值維持空白；不以 `0`、`無` 或推測內容補值。
- 表 4 的個別因素需要宗地形狀、臨路、面積等宗地證據。上傳文件與公開來源沒有證據時會維持空白，因此試算價格可能無法形成。
- 目前自動建案支援專案內的樹林住宅競賽案例 P001-00 至 P004-00。其他行政區需要對應的區段邊界、規則與正式書表映射後才能產製。
